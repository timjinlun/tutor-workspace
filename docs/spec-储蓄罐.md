# 储蓄罐与仪式感 · Spec

> 版本 0.1 · 2026-09-12 · 状态：P0 已实现；验收记录见 `储蓄罐交付.md`，P1/P2 待实现
> 目标版本：3.6（P0）、3.7（P1）、之后（P2）

## 0. 为什么做这个

独立老师这份工作**没有反馈回路**。上完两小时的课，关上门，没有同事说一句干得好；
钱是几个月后家长续费时一大笔进来的，跟"今晚这两小时"对不上号。努力和回报之间的链条是断的。

这一整套功能只做一件事：**把看不见的累积，在动作发生的那一刻变可见。**

不是加特效，是补上那条断掉的链子。

## 1. 核心概念

### 1.1 罐子 = 一个周期，不是全部历史

透明储蓄罐常驻侧边栏（「更多」和「设置」之间）。每打一次卡，一把金币落进去。

**罐子会满。满了就"倒罐"**——金币收拢成一枚厚币沉到罐底，罐子清空重新开始。
倒出来的每一罐，在统计页里变成历史上的一格。

```
侧边栏罐子   = 眼前正在攒的这一罐
倒罐时刻     = 几周一次的高光（撒花、可分享）
统计页       = 回头看的轨迹（月 / 季 / 年，每个周期都带上一周期对比）
```

罐子的节奏由**成就**驱动（攒满就倒），不是日历驱动。上课多的老师一个月能倒两罐，
这正是"我干得多"最直接的体感。统计页仍然按日历走，两套并存不冲突。

### 1.2 一枚币值多少：自适应

固定"一节课一枚"太少，没有爽感；固定"一节课 30 枚"又会让 ¥150 的课和 ¥600 的课看起来一样。

**规则：币值自适应，保证平均一节课约 30 枚。**

```
币值 = round_to_nice(最近 20 节已上课的平均收入 / 30)
nice 档位：1 / 2 / 5 / 10 / 20 / 50 / 100
```

- 平均 ¥280/节 → 币值 ¥10 → 一节 28 枚
- 平均 ¥1,200/节 → 币值 ¥50 → 一节 24 枚
- 平均 ¥80/节 → 币值 ¥2 → 一节 40 枚

**单枚币的大小按那节课的收入微调**（±15%），所以贵的课币更大——一眼看出这个月的结构，
而不只是数量。班课一次 3 个学生 = 3 组币连着落下，噼里啪啦，一次爆一堆。

币值每月初重算一次，存在 `settings.coinValue`。中途不变，避免罐子里的币突然缩水。

### 1.3 罐子容量：约等于一个月

```
容量 = round_to_nice(最近 3 个月的月均确认收入)，首次默认 ¥10,000
```

设置里可手动调（小罐 / 中罐 / 大罐 / 自定义）。容量存 `settings.jarCapacity`。

## 2. 情绪分级表 ← 最重要的设计原则

**仪式感做过头就是打扰。** 老师一天点 5 次「上完了」，每次都撒花，第三天就想卸载。

强度必须和**稀缺度**成正比：

| 时刻 | 频率 | 允许的强度 | 具体做法 |
|---|---|---|---|
| 单节课打卡 | 一天几次 | **极轻** | 钱飞到统计条 + 一把币落罐 + 可选一声轻响。不遮挡、不需点击 |
| 今日收工 | 一天一次 | **中** | 「收工」按钮出现 → 收工卡片升起 → 可生成海报 |
| 罐子攒满 | 几周一次 | **重** | 倒罐动画 + 撒花 + 成就海报 |
| 本月超过上月 | 一月一次 | **重** | 撒花 + 月报海报 |
| 年度回顾 | 一年一次 | **最重** | 全屏年报 + 海报 |

判断标准：**这个效果一年会出现多少次？** 超过 100 次的，一律做成不打断的微反馈。

## 4. 详细设计

### 4.1 储蓄罐渲染（P0-1）

**外观**：参考实物亚克力储蓄罐——一个直立圆柱，顶部有一道投币口，通体透明。

侧边栏宽 224px，减去 12px 内边距后可用 200px。罐子宽约 **160px**，高度随侧栏可用空间调整（约 **180–340px**，含底部小字），呈修长的圆柱鱼缸比例；紧接「更多」下方。此项按 2026-09-12 的实际视觉反馈更新。

按用户最新确认，使用 **原生 WebGL 2 的真实三维网格**，替代原 Canvas 2D 方案。罐体包括内外壁、厚底与具有实际开口的投币盖；金币为带倒角、凸缘和厚边的圆柱，采用参考图的金色金属质感。

支持按住罐体拖动旋转查看。模型从共享几何生成器导出为 `docs/models/savings-jar.glb` 与 `gold-coin.glb`。当前落币碰撞仍为有界二维 PBD，渲染与旋转是真三维；重力随罐体倾斜的三维颗粒模拟留待后续。

### 4.2 物理：用 PBD，不用流体方程（P0-1）

**先澄清一个概念**：金币不是流体，是**颗粒物质（granular matter）**。
学术上的正确方法是 DEM（Discrete Element Method），但它对 UI 来说太重。
真流体方程（SPH，本质是 Navier–Stokes 的粒子离散化）会让币像水一样流动，**反而丢掉"硬币"的手感**。

**采用 Position Based Dynamics（PBD，Müller et al. 2007）+ Verlet 积分**，自己写约 150 行，零依赖。

每帧：

```
1. 积分（Verlet）
   x' = x + (x - x_prev) * damping + g * dt²
   x_prev = x
   damping ≈ 0.98（模拟空气阻力和币之间的摩擦）

2. 约束求解，迭代 4 次：
   a. 币与币：两圆重叠时，各沿连心线推开 overlap/2
   b. 币与罐壁：超出圆柱内半径就拉回内壁
   c. 币与罐底：低于底面就抬回，并把竖直速度乘以 -0.25（弹一下就停）

3. 休眠检测
   连续 30 帧所有币的位移都 < 0.15px → 冻结模拟，停止 requestAnimationFrame
```

**邻居查询用空间哈希**（格子边长 = 币直径），把两两检测从 O(n²) 降到接近 O(n)。

**性能上限（硬约束）**：

| 项 | 上限 | 理由 |
|---|---|---|
| 参与物理的活跃币 | **≤ 240 枚** | 240 × 4 次迭代，M 系列芯片上单帧 < 2ms |
| 落币动画时长 | 900ms | 超过就拖沓 |
| 静止时的 CPU | **0**（完全冻结，不跑 rAF） | 侧边栏常驻，绝不允许空转 |

**币超过 240 枚怎么办**：底部最老的币"沉积"——从物理系统里移除，
把它们的最终位置烘焙进一张**静态底图**（离屏 canvas，只在沉积时重绘一次）。
原方案采用粒子→贴图；最新实现使用有界静态三维网格集合，避免旋转时露出平面贴图。

**液面高度**始终由「当前罐内金额 / 容量」决定，和实体币数量解耦——
这样"罐子越来越满"是准确的，不受渲染上限影响。

### 4.3 落币与撤销（P0-1、P0-2）

打卡后的完整动作链（三段，总计约 1.4 秒）：

```
0ms     点「上完了」，Stamp 落章（已有）
0ms     +¥280 从按钮位置飞向顶部「本月确认收入」胶囊（500ms，ease-out，飞行中缩小淡出）
500ms   胶囊数字滚动增加（300ms）
500ms   币从罐口连续落下：N 枚，每枚间隔 18ms，总计不超过 600ms
        → 落点在罐口横向随机 ±12px，初速度带一点随机
1400ms  物理静止，冻结
```

**撤销打卡时，币必须飞出来。** 不然老师会发现罐子只进不出，信任立刻崩。
撤销动画：对应数量的币从堆顶被"吸"出罐口，300ms 淡出。

`prefers-reduced-motion: reduce` 时：跳过所有飞行动画，直接更新数字和液面高度。

### 4.4 收工按钮与海报（P0-3）← 传播引擎

**触发条件**：当天已无 `status === "scheduled"` 的课，且当天至少有一节 `done`。
此时今天页的时间轴下方出现「收工」按钮（不是自动弹窗，**让老师自己点**——
主动触发的仪式感比被动弹出的强得多）。

点击后升起收工卡片，卡片上有「生成海报」。

**海报内容**（1080 × 1350，canvas 绘制，复用 `ScorecardSheet.tsx` 的画法）：

```
                9月12日 · 周六

          今天上了 3 节课，5 课时

     ●●●●●●●●●●●●●●●●●●●●●●●●●●●●
     （一排金币，视觉上呼应罐子）

        张明 · 数学      16:00 – 17:00
        李华 · 英语      18:00 – 18:45
        初二数学小班 2 人  20:00 – 21:00

        这个月已经上了 23 节
        连续第 12 天有课

                                    记一课 ←水印
```

- 右下角水印「记一课」，商业版可去除——**复用已有的 entitlement `scorecard.noWatermark`**
- 文案可以有温度（见 §5），但主角永远是数字

**怎么传到手机上**（这是关键的工程决策）：

app 是纯本地、不联网的，二维码里不能放需要服务器的链接。**方案：临时局域网 HTTP 服务。**

```
1. 主进程起一个 http server，绑定本机局域网 IP，随机端口
2. 路径带一段随机 token：http://192.168.1.7:53124/p/<32位随机>.png
3. 把这个 URL 编成二维码显示在卡片上
4. 手机连同一 Wi-Fi 扫码 → 浏览器打开图片 → 长按保存 → 发朋友圈
5. 60 秒后自动关闭服务；关闭卡片也立即关闭
```

安全上必须做到：
- **只绑局域网 IP，不绑 0.0.0.0**
- 路径带随机 token，同网段其他人猜不到
- 只服务这一个文件，不开目录
- 超时自动关，不常驻
- README 里写清楚"生成海报时会临时开一个本地端口，60 秒后自动关闭"

二维码生成需要引入 `qrcode` 依赖（纯 JS，无原生模块）。这是本 spec 里**唯一允许的新依赖**。

同时保留「保存到电脑」按钮，不想用手机的老师直接存文件。

### 4.5 倒罐仪式（P1-4）

罐内金额达到容量时，下次打卡结束后触发（不打断正在进行的打卡）：

```
1. 罐子轻轻晃一下（200ms）
2. 所有币向下收拢、旋转、融合成一枚厚币（700ms）
3. 厚币沉到罐底，罐子清空
4. 撒花（见 §4.6）
5. 升起成就卡片：「第 3 罐 · ¥10,000 · 用了 24 天」，可生成海报
```

历史罐子记录存进一张新表 `jars`：`{ id, closedAt, amount, lessons, units, days }`。
统计页可以看「已经攒满 7 罐」。

### 4.6 撒花的做法（P1-4、P1-5、P2-8）

**只在上表里标注「重」和「最重」的时刻出现。**

- canvas 粒子，60–90 片，2 秒内落完，落完立即销毁 canvas 和 rAF
- 纸片用 `--accent` 及其两个邻近色调，**不要彩虹七色**
- 纸片是细长矩形带旋转，不是圆点、不是 emoji、不是星星
- 从卡片顶部两侧射出，不是全屏顶部——**不遮挡界面**
- `prefers-reduced-motion` 时整个跳过

### 4.7 统计页周期切换（P1-6）

顶部一个 Segmented：**本月 / 本季 / 今年 / 自定义**。

**每个周期都必须带上一周期的对比**——切周期本身不产生"变化感"，**对比才产生**：

```
本月  42 节 · 78 课时 · ¥11,760
      比上月多 8 节 ↑ 多 ¥2,240
```

热力图跟着周期变粒度：本月 = 日历格；本季 = 13 周 × 7 天；今年 = 53 周 × 7 天。

底部一行总结，用具体的数字说话：

```
2026 年你上了 312 节课，陪 4 个孩子走过 1,480 小时
```

### 4.8 拖拽旋转（P2-7）

按住罐子左右拖 → 罐子绕竖直轴倾斜（最多 ±25°），**重力向量跟着旋转**，
币自然滑向新的"下方"。松手后 600ms 回正，币重新沉底。

实现上只需要把重力从 `(0, g)` 改成 `(g·sin θ, g·cos θ)`，PBD 的其他部分完全不用动——
这是选 PBD 而不是预设动画的最大回报。

拖拽时唤醒物理，松手回正并静止后重新冻结。

## 5. 文案原则

**可以有温度，但温度必须来自具体的数据，不是形容词。**

| ❌ 空洞 | ✅ 具体 |
|---|---|
| 今天辛苦了，你真棒！ | 今天你陪 4 个孩子上了 5 小时的课 |
| 坚持就是胜利 ✨ | 连续第 12 天有课，这个月一天没断 |
| 收入又增长啦！ | 这个月比上个月多上了 8 节 |
| 感谢你的付出 | 张明从 20 节用到只剩 3 节，一次没落下 |

右边这些话只有**这个 app** 说得出来，左边任何一个 app 都能说。这就是区别。

其他规则：

- **温度只出现在稀缺时刻**（收工、倒罐、月报、年报），单节课打卡永远只有数字
- 不用感叹号堆砌，一段话最多一个
- 不用「亲爱的老师」这类称呼，直接说事
- emoji 整张卡片最多一个，且只在标题旁

## 6. 技术约束（照抄，不要改）

- Electron 43 + React 19 + TypeScript strict（无 `any`、无 `ts-ignore`）
- 动画用已有的 `motion`；画图用原生 canvas 2D
- **唯一允许新增的依赖：`qrcode`**（纯 JS）。物理、粒子、罐子全部手写
- 样式是手写 CSS + CSS 变量。**颜色一律用变量**（`--accent` `--label` `--surface` `--line` …），
  写死颜色深色模式就坏
- CSP 是 `default-src 'self'`：**不能加载外部资源，不能用 data: URI 的音频**。
  音效必须用 Web Audio 现场合成（AudioContext + Oscillator）
- 分层规则（下层不能 import 上层，features 之间不能互相 import）：

  ```
  core（纯函数，不认识 React）
    → store（zustand）
      → ui/primitives（通用组件，不认识业务）
      → ui/widgets（业务组件，可以用 store）
        → ui/features/*（页面）
  ```

- **所有计算逻辑写成 core 纯函数 + vitest 单测**，组件只做渲染。
  需要的纯函数：`coinValue()` `jarState()` `streakDays()` `periodStats()` `yearHeatmap()`
- 不改现有数据库 schema，除了新增 `jars` 表和 `settings` 的两个字段

## 7. 不做的事

- ❌ 引入物理引擎（matter.js / planck.js）——PBD 手写 150 行就够，且可控
- ❌ 常驻的 requestAnimationFrame——静止时必须完全冻结
- ❌ 卡通金币、金黄渐变、闪光特效
- ❌ 全屏遮罩的庆祝（撒花只从卡片射出，不盖住界面）
- ❌ 自动弹出的收工卡片（让老师自己点「收工」）
- ❌ 每次打卡都庆祝

## 9. P0 落地确认（2026-09-12）

- 第一罐包含全部已确认收入，超容量仅显示满罐与实际金额；倒罐留到 P1。
- `settings.coinValue` 使用 `{ amount, month }`，在两个设置字段限制内持久化月度锁定。
- 班课海报按场次与教学课时计数，3 人上 2 课时 = 1 节、2 课时；金额仍按学员实际扣费累计。
- 参考图片用于硬币形状、厚度和透明圆柱结构，硬币采用金色金属材质。海报使用暖白纸感。
- 静态币堆采用有界三维网格集合，金额变化时重建；不持久化每枚币坐标。性能数据、截图与手机实测边界见交付记录。

- 最新视觉反馈：罐体加长为圆柱鱼缸般的比例，紧接「更多」下方，硬币尺寸不随罐高拉伸。小窗口自适应高度，避免遮挡设置入口。

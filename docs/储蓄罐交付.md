现有代码接入位置：

- core/types.ts：Settings 和 DEFAULT_SETTINGS 增加 coinValue、jarCapacity。

瞬时接口：`JarFeedback { seq, changes: { id, amount }[] }`，不进入 State/数据库。负 amount 表示撤销。
持久接口：`coinValue: { amount: number; month: string }`、`jarCapacity: number`；沿用现有 SQLite settings 键值存储，无新表。

取舍：静止币堆按金额重建为有限三维网格集合，不保存每枚历史币的位置，以确保内存有界、撤销准确、空闲无动画循环。

验证：51 tests PASS；typecheck PASS；build PASS；Electron 空/半满/接近满/深色截图已检查，空闲 1 秒 rAF 增量为 0。
截图与机器证据：qa/jar/。

## 收尾与验收

- 审查修复：连续两次打卡不会覆盖待发射币；撤销按课程ID移除；待办等无关状态不结束动画。Electron 实测两笔 ¥280 共发射56枚。
- useLocalDay 在午夜/窗口恢复焦点时刷新日期，不持续轮询；币值跨月更新。
- 海报单测覆盖水印权益、长名称和9节课的溢出汇总。
- HTTP单测使用回环地址便于离线CI；生产地址筛选单独测试，正式Electron使用真实局域网地址验收。
- 正式Electron隔离目录验收：PNG为1080×1350，二维码可见，HTTP 200，返回字节和海报一致，保存到电脑的文件也一致，关闭卡片后链接失效。证据见 qa/closing/evidence.json。
- 手机相机扫码、手机浏览器长按保存未使用实体手机验证，不将桌面HTTP测试表述为手机实测。
- 性能脚本区分实际240枚/600ms发射与额外240枚瞬间加入的压力场景；后者冷启动可能超过2ms，不作硬实时保证。结果见 qa/jar/performance.json。
- 原有CSP内联外观恢复脚本告警和 ESLint 边界配置弃用提示已记录，未降低CSP或做无关规则迁移。

复跑：npm test；npm run typecheck；npm run lint；npm run build；node scripts/benchmark-jar.mjs；./node_modules/.bin/electron scripts/verify-jar.cjs；./node_modules/.bin/electron scripts/verify-closing.cjs。
验收脚本只使用临时用户目录、内存或临时SQLite和虚构学员，不打开正式数据库。截图中的二维码来自已关闭的测试会话。
